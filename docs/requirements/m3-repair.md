# M3 物业报修工单需求

- 状态：草稿，待 M1、D 与项目负责人评审
- 日期：2026-10-21
- 设计：`docs/specs/m3-repair.md`
- 一致性决策：ADR-0009

任务书明确要求 M3 提供故障上报、派单、维修中状态、超时升级、完工验收与评价，并要求维修中的工单使 M1 下架该室全部座位，验收通过后恢复。任务书未规定角色细节、超时数值和存量预约处理；本文件给出首版可执行规则，跨模块部分经相关模块评审后转为“已确认”。

## 首版业务决定

1. 登录用户可以报修；物业管理员负责派单、改派和验收；被指派的维修人员负责开始维修和提交完工。
2. 维修人员不能给自己或他人改派。物业管理员只能在尚未开始维修的 `ASSIGNED` 阶段改派；开工后的人员变更留作后续需求。
3. 验收由具有该空间管理权限的物业管理员执行，维修人员不得验收自己参与的工单。报修人在工单完成后评价，评价不代替验收。
4. 首版按自然时间计时：待派单 2 小时、待开工 4 小时、待验收 4 小时；维修期限由派单时填写，未填写时默认 24 小时。阈值均为配置项。
5. 阶段到期触发一级升级，通知当前处理人和空间范围内的物业管理员；再逾期 4 小时触发二级升级，通知物业主管/系统管理员。每个阶段周期的每一级只登记一次。
6. 维修限制立即阻止新预约。已有及进行中的预约不删除：由 M1 标记为“因维修受影响/取消”，保留原记录，不计学生违约，并通知相关用户；M3 只发起限制操作，不直接修改 M1 预约表。
7. D 的身份权限能力落地前，生产接口不得相信请求体中的用户 ID 或角色；通知和审计先以本地待投递记录保存，D 不可用不回滚已经成立的业务事实。

### REQ-M3-001 上报故障
- 状态：草稿
- 来源：任务书第二节 M3 主要功能
- 描述：登录用户选择 D 中启用的教室，上报故障分类和描述。报修人取自可信用户上下文，客户端通过 `Idempotency-Key` 保证重试不重复建单。
- 验收标准：
  1. 对启用教室提交合法分类和非空描述，生成一张 `SUBMITTED` 工单；
  2. 教室不存在或 `available=false` 时拒绝创建；D 不可用时返回明确的 503，且不产生工单；
  3. 同一报修人以同一幂等键重复相同请求，只返回原工单；同键不同内容返回 409；
  4. 请求体中的 `reporterId` 或角色字段即使存在也不参与授权和落库。

### REQ-M3-002 查询工单与过程追溯
- 状态：草稿

- 描述：报修人查看自己的工单，维修人员查看被指派工单，物业管理员查看其管辖空间内工单；详情展示状态、动作时间线、升级和跨服务同步状态。

### REQ-M3-003 派单与改派
- 状态：草稿
- 来源：任务书第二节 M3 主要功能；本文件首版决定 1、2
- 描述：空间范围内的物业管理员把 `SUBMITTED` 工单指派给有效维修人员；仅在 `ASSIGNED` 且尚未开工时允许管理员改派并填写理由。
- 验收标准：
  1. 普通用户和维修人员不能派单或改派；
  2. 无空间管辖权的管理员不能操作；无效维修人员不能被指派；
  3. 并发派单只有一个成功，改派保留前后人员和理由；
  4. `STARTING` 及之后状态拒绝改派。

### REQ-M3-004 开始维修并下架整室座位
- 状态：草稿
- 来源：任务书第二节 M3→M1 写回
- 描述：被指派人员开始维修时，M3 持久化下架意图并调用 M1；只有 M1 确认本工单的 M3 限制生效后，工单才进入 `IN_PROGRESS`。
- 验收标准：
  1. 非被指派人员、非 `ASSIGNED` 工单不能开始维修；
  2. 操作期间状态为 `STARTING`，结果未知时保持该状态并可自动恢复，不能假装失败或成功；
  3. M1 确认后，该室全部座位不能产生新预约，限制来源为 `M3` 且关联工单 ID；
  4. 同一操作重试不产生第二条限制；同键不同内容被拒绝。

### REQ-M3-005 处理已有预约
- 状态：草稿
- 来源：任务书“从可预约列表下架”；工程伦理中的安全、公平与可追溯要求
- 描述：维修限制建立时，M1 负责处理该室与维修时段重叠的预约。记录不得被物理删除，也不得把维修造成的无法履约记作学生违约。
- 验收标准：
  1. 限制生效后立即拒绝新预约和签到使用；
  2. 已有预约保留原始记录，并标记为因维修受影响或取消；
  3. 受影响用户和物业管理员收到通知；通知失败可补发，不撤销维修限制；
  4. M3 不直接访问或修改 `seat_db`。
- 实现：M1 与 D 联合实现；M3 负责发起操作并保存返回摘要
- 验证：跨模块集成测试

### REQ-M3-006 提交完工

- 描述：被指派维修人员对 `IN_PROGRESS` 工单提交非空完工说明，工单进入 `PENDING_ACCEPTANCE`，维修限制继续有效。

### REQ-M3-007 验收与精确恢复
- 状态：草稿
- 来源：任务书第二节“完工验收”及 M3→M1 写回；本文件首版决定 3
- 描述：具有空间权限的物业管理员验收，且不能是本工单维修人员。验收不通过须填写理由并返回维修中；验收通过后仅解除本工单对应的 M3 限制。
- 验收标准：
  1. 报修人、普通用户、无管辖权管理员及本工单维修人员不能验收；
  2. 不通过时状态回到 `IN_PROGRESS`，保留限制并开启新的维修阶段周期；
  3. 通过时进入 `RESTORING`，M1 确认精确解除后才进入 `COMPLETED`；
  4. 同室另一张维修工单或 M2 占用仍存在时，不得错误恢复对应座位；
  5. 解除响应丢失时可按原操作 ID 查询或重试，不能重复解除其他限制。

### REQ-M3-008 完成后评价
- 状态：草稿

- 描述：报修人可在 `COMPLETED` 后提交一次 1 至 5 分评价和可选文字；评价不改变验收结论。
- 验收标准：
  1. 非报修人、未完成工单和范围外评分被拒绝；
  2. 每张工单最多一条评价，重复相同请求返回原结果；
  3. 评价内容不写入普通运行日志，权限外用户不可见。

### REQ-M3-009 超时升级
- 状态：草稿
- 来源：任务书第二节 M3 主要功能；本文件首版决定 4、5
- 描述：系统按阶段期限识别超时并逐级升级。待派单 2 小时、待开工 4 小时、待验收 4 小时；维修期限由派单时指定，默认 24 小时。一级到期触发，二级在一级后 4 小时触发，数值均可配置。
- 验收标准：
  1. 到期前不升级，到期点登记一级升级，再逾期 4 小时登记二级升级；
  2. 一级通知当前处理人和物业管理员，二级通知物业主管/系统管理员；
  3. 同一工单、阶段周期和级别最多一条升级记录，多实例扫描和重启不重复；
  4. 工单进入下一阶段后，旧阶段不再升级；返修使用新阶段周期；
  5. D 通知不可用时保留待投递记录，升级事实仍成立。

### REQ-M3-010 跨服务故障恢复与审计
- 状态：草稿
- 来源：任务书跨模块写回、追溯和工程化要求；ADR-0009
- 描述：M3 与 M1/D 的写入不依赖分布式事务，使用本地操作记录、下游幂等接口和恢复任务保证最终一致；所有关键动作可审计。
- 验收标准：
  1. M1 未收到请求、成功但响应丢失、M3 确认落库前重启等场景最终可恢复；
  2. 已解除的限制不会因旧的下架请求重放而复活；
  3. 下游不可用不使 M3 `/actuator/health` 变为 DOWN；
  4. 日志和错误响应不包含报修正文、评价、联系方式、令牌或内部异常信息。

### REQ-M3-011 取消未开工工单
- 状态：草稿
- 来源：任务书第五节附加项的 M3 操作示例；首版辅助能力
- 描述：报修人或有权限的物业管理员可以取消 `SUBMITTED` 或 `ASSIGNED` 工单；开始维修后不能用取消绕过验收和恢复流程。
- 验收标准：
  1. 报修人只能取消自己的未开工工单，管理员只能取消管辖空间内工单；
  2. 取消与开始维修并发时只有一个合法转换成功；
  3. `STARTING` 及之后状态拒绝取消；取消不影响其他工单或限制。
