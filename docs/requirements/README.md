# 需求基线

每条需求一个编号，**没有验收标准的需求不算完整需求**。未完成的需求改状态，不删除。

## 编号规则

`REQ-<模块>-<三位序号>`，模块为 `M1` `M2` `M3` `D` `X`（跨模块）。如 `REQ-M1-003`、`REQ-X-001`。

## 状态

`草稿` → `已确认` → `开发中` → `已完成` / `已延期` / `已放弃`（后两者写明原因）

## 单条需求格式

```markdown
### REQ-M1-003 预约时段限制
- 状态：已确认
- 来源：任务书附件 1 第 2 条
- 描述：学生预约以整点小时为单位，单次最多 4 小时（系统参数可调）。
- 验收标准：
  1. 预约 09:00–13:00 成功；
  2. 预约 09:00–14:00 被拒绝，提示超过上限；
  3. 预约 09:30–10:30 被拒绝，提示需整点；
  4. 管理员把上限改为 3 后，09:00–13:00 被拒绝。
- 实现：（PR 链接 / 代码位置）
- 验证：（测试类名 / 手动验收记录）
```

## 文件组织

每个模块一个文件：`m1-seat.md`、`m2-room.md`、`m3-repair.md`、`d-platform.md`、`x-integration.md`。
