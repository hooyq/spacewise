# ADR-0002：后端采用 Spring Boot 3.5（而非 4.x）

- 状态：提议中（待组内确认）
- 日期：2026-10-20
- 决策人：（待填）
- 相关：ADR-0001；搭建路线第 2 步

## 背景

技术栈已定为 Java 21 + Spring Boot + Maven。当前 Spring Boot 有两条可用的主线：3.5.x 与 4.x。
约束：组员多数初学 Spring；大量依赖网上教程与 AI 助手生成代码；后续要用 Spring Cloud Gateway 做网关；
学期内完成，不希望在框架升级问题上耗时。

## 候选方案

### 方案 A：Spring Boot 3.5.x
- 优点：教程、问答和 AI 训练资料以 3.x 为主，示例代码基本能直接用；Spring Cloud 对应版本成熟；
  Java 21 完整支持。
- 缺点：不是最新主线，学期结束后离停止开源支持更近；以后升级 4.x 需要迁移。

### 方案 B：Spring Boot 4.x
- 优点：最新主线，支持周期更长；能接触新特性。
- 缺点：改动较大（如 Jackson 3、模块拆分、部分 API 移除），AI 和教程给出的 3.x 写法可能编译不过或行为不同，
  初学者难以分辨是自己写错还是版本差异；部分三方库适配滞后。

<!-- 候选方案由 AI 提出，人确认选择 A。 -->

## 决定

选择 **方案 A：Spring Boot 3.5.x**（初始版本 3.5.16），由根 `pom.xml` 继承 `spring-boot-starter-parent` 统一管理。

## 依据

最关键的因素是**学习与排错成本**：课程考核过程而非框架新旧，3.5 让组员和 AI 的示例“对得上”，
把精力留给需求、测试与流水线。

## 代价与后续

- 接受“不是最新版”的代价；版本号只在根 POM 一处维护，升级补丁版本只改一行。
- 若课程后期需要 4.x 才有的特性，或 3.5 停止维护影响到依赖安全，再单独评估升级。
